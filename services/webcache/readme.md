Centralized web cache, basically cold storage for web pages that have been visited by a scraper. app should include storage options for local disk as well as s3 style storage, basic api should be built to support cache functionality. if grpc makes more sense then lets use it, otherwise rest is fine. cached pages should be stored using lz4 compression and one file per page. cache should use a database to keep track of web pages stored and when they were added, use sqlalchemy as the orm and sqlite to start with. let's keep the service open with no security for now. when a client posts a new page it should persist the url, content, lookup time, and client_name from the request. generate a checksum hash using the page content and a non-colliding algorithm, make the hash the file-name to avoid duplication in the cache. basic http codes should be followed, 404 when cache entries are not found, etc. cache queries should be by url typically, i'd like to include a client-side ability to query for a sub-string of the url, for example query by url with any query parameters and get all results. I'd also like to have python client package that i can import to other projects and a docker-compose to run the cache locally. i do want to keep all of the files though so the storage volume should be to a real disk location rather than a generic docker volume. Please build the project in this webcache folder, include relevant documentation in a docs/ folder, tests in a tests/ folder
